## What was built

### Backend

**Migrations**
- `006-students-core.ts` — creates `student_categories`, `student_houses`, `students`, `student_profiles` tables with all indexes and constraints
- `007-students-guardians-enrollments.ts` — creates `guardians`, `student_guardians`, `student_enrollments` tables; unique index enforces one active enrollment per student per academic year

**Entities (7)**
- `StudentCategoryEntity` — GEN/SC/ST/OBC/EWS categories
- `StudentHouseEntity` — Red/Blue/Green/Yellow houses
- `StudentEntity` — core identity: admission_no, name, DOB, gender, blood_group, religion, caste, nationality, aadhaar_no, category_id, house_id, status, soft-delete
- `StudentProfileEntity` — extended profile: address, emergency contact, previous school, transport mode
- `GuardianEntity` — guardian record with occupation, income, education
- `StudentGuardianEntity` — pivot: student ↔ guardian with relation, is_primary, emergency_contact flags
- `StudentEnrollmentEntity` — enrollment per academic year with roll_number, status

## Architecture decisions
- `school_id` first on all composite indexes
- Soft-delete: `deleted_at` + status `inactive` (never hard delete)
- Enrollment enforces single active record per student per academic year (partial unique index)
- BullMQ queue `STUDENTS_BULK_IMPORT_QUEUE` handles async CSV processing
- Guardian portal account creation (optional): creates `User` + `SchoolMembership` with `parent` role
- `synchronize: false` maintained throughout
