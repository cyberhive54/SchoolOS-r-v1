## Architecture Decisions Made

### 1. Monorepo Structure
- **Turborepo + pnpm workspaces** — industry standard for this stack
- Root: `apps/*` (api, web) + `packages/*` (types, config, ui)
- Pre-existing Replit `artifacts/` and `lib/` preserved for environment compatibility

### 2. TypeScript Config Strategy
- Created `tsconfig.nestjs.json` as a separate base (CommonJS + decorators) rather than replacing the Replit-inherited `tsconfig.base.json`
- NestJS API extends this base; Next.js web uses bundler resolution separately
- Prevents conflict between CommonJS (NestJS requirement) and ESM (Next.js/Vite)

### 3. Multi-tenancy Resolution (TenantMiddleware)
Three-strategy resolution in priority order:
1. `X-School-ID` header (UUID) — for API clients and local dev
2. Subdomain of `Host` header — e.g. `springfield.schoolos.com` → slug `springfield`
3. Custom `domain` field match — e.g. `erp.springfieldschool.edu`

### 4. Auth Flow
- **Step 1** (POST /v1/auth/login): Validate credentials → generate 6-digit OTP → store bcrypt hash in `otp_requests` → send to email (dev: console.log)
- **Step 2** (POST /v1/auth/verify-otp): Verify OTP hash → issue JWT (15min, HS256) + refresh token (7d, HttpOnly+Secure+SameSite=Strict cookie, stored as bcrypt hash in `user_sessions`)
- **Refresh** (POST /v1/auth/refresh): Verify session → rotate refresh token (revoke old, create new) → return new access token
- **Logout** (POST /v1/auth/logout): Revoke session matching refresh token cookie → clear cookie

### 5. Token Security
- Access token: JWT in response body → stored in **Zustand JS memory ONLY** (never localStorage/sessionStorage)
- Refresh token: HttpOnly + Secure + SameSite=Strict cookie → stored as **bcrypt hash** in DB (never raw token)
- Rotation on every refresh call

### 6. RBAC / PBAC
- PermissionsGuard checks `role_permissions` table
- super_admin bypasses table check (handled at guard level)
- Permissions cached in-memory (Map); invalidated on updates
- Default permission sets for all 7 roles seeded in `seed.ts`

### 7. Database Schema Rules Followed
- `synchronize: false` — migrations only
- All PKs: UUID (gen_random_uuid())
- All timestamps: TIMESTAMPTZ (timezone-aware)
- All tenant tables: `school_id` first in every composite index
- `audit_logs` table has `fillfactor=70` for append-heavy workload

### 8. Response Envelope
- Success: `{ "data": ... }` (single) or `{ "data": [...], "meta": {...} }` (paginated)
- Error: `{ "error": { "code": "UPPER_SNAKE", "message": "...", "details": {} } }`
- Global `AllExceptionsFilter` catches ALL exceptions — stack traces never exposed
- Global `ResponseTransformInterceptor` wraps all success responses

# Seed development data
pnpm schoolos:seed

# API: http://localhost:4000/v1/healthz
# Web: http://localhost:3000
# Demo credentials: admin@demo.schoolos.com / Admin@123
