## Bugs Found & Fixed

### CRITICAL — Frontend had no env file
- **File created:** `frontend/.env.local`
- **Problem:** Without this file, all frontend API calls were hitting `http://localhost:4000/v1` (Docker port) instead of `http://localhost:3001/v1` (Replit port), AND the `X-School-ID` header was empty, causing every request to fail with `SCHOOL_NOT_FOUND`.
- **Fix:**
  ```
  NEXT_PUBLIC_API_URL=http://localhost:3001/v1
  NEXT_PUBLIC_SCHOOL_ID=12e9720e-4f8e-4630-8bc1-ca7c6a1cfca9
  NEXT_PUBLIC_PLATFORM_DOMAIN=localhost
  ```
- **Impact:** Login, all data-fetching pages (Students, Academics) and API calls were completely broken before this fix.

### CRITICAL — Case-sensitive UI component imports (5 files)
- **Problem:** All student pages imported `from '@/components/ui/Badge'` (uppercase B) but the file is `badge.tsx` (lowercase). On Linux (Replit), this causes module-not-found errors at runtime.
- **Files fixed:**
  - `frontend/src/app/(dashboard)/students/page.tsx`
  - `frontend/src/app/(dashboard)/students/[id]/page.tsx`
  - `frontend/src/app/(dashboard)/students/bulk-import/page.tsx`
  - `frontend/src/app/(dashboard)/students/settings/page.tsx`
  - `frontend/src/components/students/AddStudentSlideOver.tsx`
- **Fix:** Changed all imports to lowercase (`badge`, `button`, `input`, `card`, `skeleton`, `dialog`)

### UX — No success message after OTP login
- **Problem:** After successful OTP verification, the app silently redirected to `/` with no feedback.
- **Fix:**
  - `OtpForm.tsx`: Changed `router.push('/')` to `router.push('/?login=success')`
  - `dashboard/page.tsx`: Added a green flash banner that reads "Signed in successfully. Welcome back, {firstName}!" — auto-dismisses after 5 seconds, has an × close button

### Maintenance — Redis config (exponential backoff)
- **Problem:** BullMQ retried Redis every ~1 second, flooding the log with `Error: connect ECONNREFUSED`.
- **Fix:** Updated `backend/src/config/redis.config.ts` to set `retryStrategy: (times) => Math.min(times * 1000, 30_000)` — exponential backoff capping at 30s.
- **Note:** The errors are emitted by ioredis before the retry strategy kicks in; the BullMQ-level error event still surfaces to stderr. This is an ioredis/BullMQ integration limitation. The fix reduces frequency significantly after the first few attempts.

## OTP Design Answer (for product decision)
**Current behaviour:** OTP is required on **every login** (mandatory 2FA).

**Alternatives available for future configuration:**
- **Always required (current)** — Maximum security; every session needs OTP. Suitable for school admin/finance roles.
- **Once per device** — OTP only when logging in from a new device/browser (trust cookie). Better UX.
- **Admin-only 2FA** — Students/parents use password only; admins/staff require OTP. Common in ERP systems.

The current implementation stores OTP as a hash in `otp_requests` table with 10-minute expiry and 5-attempt limit. Changing to device-trust would require adding a `trusted_devices` table and `remember_device` flow.
