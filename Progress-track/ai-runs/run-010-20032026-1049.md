# Run 010 — 20 Mar 2026, 10:49

## Goal
Fix persistent hydration mismatch error on the login page (Next.js 15 App Router).

## Root Cause Identified
`ServerThemeInjector` (an async Server Component returning a `<style>` tag) was placed inside a manually rendered `<head>` element in `frontend/src/app/layout.tsx`.

In Next.js 15 App Router, when you combine:
- A manual `<head>` element in the root layout
- The `metadata` export (which Next.js also injects into `<head>`)
- An async Server Component inside that `<head>`

...Next.js's internal head reconciliation system places the Next.js-managed tags and the component-rendered tags in a different order between SSR HTML and client hydration. React detects the ordering difference and throws:

> "Hydration failed because the server rendered HTML didn't match the client."

This was confirmed by fetching the raw SSR HTML and seeing the `<style id="schoolos-theme">` injected between `<meta name="description">` and the polyfills `<script>` — a position determined by the server-side render order but not guaranteed to match client-side reconciliation.

## Fix Applied
**File:** `frontend/src/app/layout.tsx`

Removed the manual `<head>` element entirely (Next.js manages `<head>` via the `metadata` export). Moved `<ServerThemeInjector />` to the very top of `<body>`, before `<Providers>`.

A `<style>` element inside `<body>` is valid HTML5 and applies globally. This completely avoids the head reconciliation conflict.

```diff
- <html lang="en" suppressHydrationWarning>
-   <head>
-     <ServerThemeInjector />
-   </head>
-   <body>
-     <Providers>{children}</Providers>
-   </body>
+ <html lang="en" suppressHydrationWarning>
+   <body>
+     <ServerThemeInjector />
+     <Providers>{children}</Providers>
+   </body>
```

## Result
- Browser console: **zero errors** after fix (previously `unhandlederror` hydration mismatch on every page load)
- Frontend compiles cleanly, `GET /login 200` in ~57ms
- Login page renders correctly with school theme colors applied
- Backend Redis ECONNREFUSED errors are expected/harmless (Redis not available in Replit)
